# 封面导出谱面帧 v1 复刻设计

## 背景

封面导出最近将谱面帧预览改成了“进入页面后异步捕捉所有可见帧”。在 macOS 上，捕捉用的不可见 `QQuickWindow` 可能没有暴露，导致捕捉始终失败；为了避免此前的 scene graph 崩溃，安全门又把失败明确显示成“无法捕捉谱面帧”。结果是首屏空白，点击图层后才可能触发实时场景。

成熟 v1 的实际机制不同：封面编辑器内嵌一个可见的 Quick 场景，当前活动谱面帧直接使用共享 `PreviewFrameState` 绘制。拖动时间、播放和切层只更新共享状态；静态抓帧只用于活动帧离开实时场景、图层启用/添加和最终导出。

## 目标

1. 进入封面导出后，在布局和谱面数据可用时立即显示对应谱面帧，不依赖 offscreen grab 成功。
2. 恢复 v1 的布局恢复语义：有可见谱面帧时，首个可见谱面帧成为活动实时帧；没有时保持卡片活动。
3. 播放、暂停、进度拖动、方向键继续作用于共享播放状态；播放到末尾停止并停在末尾，再次播放从起点开始。
4. 保留最终导出所需的静态图捕捉和此前的 segfault 防护。
5. 捕捉失败不能清掉已有静态缓存，也不能在进入页面时阻塞或弹出错误。

## 非目标

- 不重新引入 v1 已删除的 QWidget 面板。
- 不让 QML 预览通过反复截图驱动播放或拖动。
- 不使用嵌套事件循环、休眠或后台线程调用 `QQuickWindow::grabWindow()`。

## 设计

### 1. 进入流程

`QmlCoverExportSession::seedFromDifficulty()` 按以下顺序工作：

1. 停止旧播放并解除旧实时场景。
2. 创建并 bootstrap 当前难度的 `SceneFrameRenderer`，得到共享 `PreviewFrameState`。
3. 恢复持久化布局和图层属性。
4. 从可见谱面帧中选择第一个作为活动图层；若没有可见谱面帧则选择卡片。
5. 将该图层的 `frameSeconds` 写入共享状态，完成 playback 同步并绑定 QML 的实时 `PreviewQuickSceneRoot`。
6. 直接结束进入流程，不把静态捕捉结果作为页面可用条件。

QML `CoverComposer` 继续只让 `activeChartFrameKey` 对应的图层创建实时谱面场景。实时场景的绘制来自共享状态，因此进入后无需点击图层或等待静态图。

### 2. 活动图层和静态缓存

切换图层前，若旧活动图层是谱面帧，则尝试把其当前时间捕捉到静态缓存；捕捉失败时保留旧缓存，不显示错误。随后把新活动谱面帧绑定为实时场景，保证新选择的帧立即可见。

非活动谱面帧使用 `image://coverchart` 静态图。其缓存只在新增、启用、切出实时状态或导出时更新；不能因为一次失败而清空已有图像。

进入流程不再启动“捕捉所有可见谱面帧”的重试定时器，也不因其超时调用用户可见错误通知。最终导出仍必须为所有可见谱面帧准备静态图，失败时由导出流程报告失败。

### 3. 捕捉安全

`SceneFrameRenderer` 保留 GUI 线程限定和 scene graph/RHI 生命周期检查，继续禁止嵌套 `processEvents()`、休眠和跨线程抓帧。捕捉窗口只服务于静态图和最终导出，不再承担首屏预览职责；其生命周期和暴露状态需要按 v1 的可用窗口语义调整，避免永久停留在 macOS 不可暴露的屏幕外位置。

### 4. 回归覆盖

- 进入包含可见谱面帧的布局后，活动图层是第一个可见谱面帧，并绑定实时场景。
- 进入包含多个谱面帧的布局时，活动帧走实时路径，其他帧保留/使用静态缓存。
- 进入时不调用预览捕捉重试，也不因捕捉未就绪通知错误。
- 切层、时间拖动、播放到末尾和再次播放符合 v1 语义。
- 静态捕捉失败不清空已有缓存；最终导出仍检查所有可见谱面帧。
- 现有 segfault 回归和 QML 合同测试继续通过。

## 方案取舍

采用“v1 实时优先 + 静态捕捉按需”的方案。它复刻了 v1 的用户可见状态机，同时保留 v2 当前 QML 布局和共享状态边界；不把 macOS 对隐藏 Quick 窗口的暴露行为当成首屏依赖，也不需要恢复整套旧 QWidget 编辑器。
