# 三平台 CI 重构

三个平台通过 `.github/workflows/package.yml` 的矩阵作业运行，权重与验收要求相同。作业失败会停止该平台的后续步骤，运行中的其他平台继续完成；工作流并发配置保留排队，运行任务保持执行。

| Windows x64 | MSVC 2022、Ninja Multi-Config、Qt 6.11.1 | 预览使用裁剪版 7.1；导出使用 Gyan 7.1.1 essentials | 77–79 MiB，验收门槛 < 80 MiB |

## 缓存与输入

每个平台具有 Qt、FFmpeg、sccache 编译器输出、CMake 构建目录、成品五层缓存。`platform-v1` 命名空间用于本次冷构建验收，第二轮复用同一提交和命名空间。

输入标识来自 Git 跟踪文件的对象编号，覆盖应用、资源、LFS 指针、子模块提交、构建与打包脚本、许可证、工作流。验证脚本不进入成品标识。成品命中后跳过 LFS 下载、依赖恢复、配置、编译和压缩，检查成品 SHA256、平台、输入标识及包体后上传。成品缓存保存 7z 与功能验证记录。文档与验证脚本变更保持包输入标识稳定。

Qt 与 FFmpeg 采用精确键；编译器输出与构建目录允许同工具链前缀复用。构建缓存键覆盖运行器镜像版本和构建配方。Windows 构建缓存于成功作业结束时保存。macOS 在编译和打包成功后保存四层构建缓存，功能检查随后执行。编译缓存前缀只依据各平台构建与打包脚本生成。验证脚本变更复用成品包；工作流步骤变更复用编译成果。成品通过功能与体积检查后进入成品缓存。

手动运行的 `macos_only` 选项用于 macOS 修复验收；常规运行覆盖三个平台。

macOS 的显式保存键与恢复键一致，保存后通过 GitHub API 检查四条缓存记录及非零体积。运行 34749496034 保留的压缩包通过本机架构及 H.264/AAC 编解码检查。

Windows 编译器探测使用请求的构建配置，Release 探测采用 Release 编译参数，修复历史运行中 sccache 寻找 Debug PDB 导致配置失败的问题。应用及后端源文件沿用基础分支。

## 验收与测量

冷构建检查 Windows 包结构、DLL 依赖、程序架构；macOS 检查包依赖、部署版本、arm64 架构。三个平台使用包内 FFmpeg 生成 H.264/AAC 媒体并解码，记录版本与结果。这些检查覆盖打包契约与媒体工具链，交互编辑、谱面预览和完整导出流程需要专门的应用功能验收。

每个作业摘要记录出包耗时、包体和触发时间。出包计时从作业计时步骤持续至上传完成，成品命中轮要求小于 60 秒；GitHub 作业时间另行记录，包含作业准备与收尾，排队时间单列。

本次运行数据待三平台冷构建与相同输入缓存构建完成后填写。
