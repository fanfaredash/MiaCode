# Design Ledger

Use this file to separate hard contracts from adjustable implementation choices.

## 1. Source Of Truth Rule

- Code is the source of truth.
- `docs/specs/preview/PREVIEW_RUNTIME_EXPORT_ARCHITECTURE_SPEC.md` and other notes are guidance and memory aids.
- When docs and code diverge, trust code first, then update the docs.

## 2. Must-Keep Contracts

- `MainWindow` is orchestration, not the long-term home for every feature body.
  - New window features should normally land in `src/app/mainwindow/sections/<feature>/`.
- `SimaiDocument` is the editable storage model for metadata and difficulty text.
- Parser output is the shared intermediate representation for:
  - timeline
  - preview
  - Muri analysis
  - export reconstruction
- Simai backtick separators accept a consecutive run of `` ` `` characters as input compatibility, but the run collapses to a single backtick separator: it splits each-groups without adding a timing gap, and strict validation still requires notes on both sides of the run.
- Runtime SFX and export SFX must use the same note-to-sound semantics.
- `&first` is stored as raw document data; timing semantics are applied through getters and marker shifting instead of ad-hoc inversion scattered around the codebase.
- Preview timing semantics now follow the current preview contract: raw `&first` is parsed directly into preview/export/tooling `firstSeconds` without a second inverted helper layer, preview `audioOffset` acts as a chart-domain whole-SFX shift, positive `displayOffset` advances the `answer` / `judge` families, `answerOffset` stays answer-only, `judgeOffset` stays judge-only, and slide / break-slide / touchhold-sustain / firework-anchor timing keeps only the global chart-domain shift.
- Realtime preview BGM timing is currently backend-owned by platform: Windows uses the BASS/BASSmix runtime path for all playback rates and defaults BGM rate changes to pitch-preserving BASS_FX tempo with the compact `40/15/8` window preset; `MIACODE_BASS_BGM_RATE_MODE=rate_transpose` remains as a diagnostic A/B switch to source-time-priority rate transpose (`BASS_ATTRIB_FREQ`) when waveform alignment needs to be isolated. The non-Windows compatibility backend still uses the stretched `SoundTouch` runtime path for all playback rates, including `1.0x`; where a stretched path is active, authoritative preview audio time must come from an engine-time anchor (`ma_engine_get_time_in_pcm_frames()` + chart start second), not from a stretched data-source cursor.
- Export uses a snapshot/worker boundary rather than mutating UI state from the worker process.
- Asset lookup is file-based and convention-driven, not database-driven.
- Live preview QSG textures are owned by one render-side root-node/window generation. Every reset or teardown must destroy referencing nodes/materials before textures; GUI-side invalidation can request that reset but cannot directly clear live QSG resources.

## 3. Current Defaults That Are Adjustable

- Preview canvas default aspect ratio is square unless temporarily changed by export UI.
- Preview Tap/Touch flow speeds both default to the shared value in `PreviewGameplayConfig.h`; persisted settings now store them separately, while older single-speed settings still fan out to both on load.
- Native chart-review preview currently stacks an extra maimuri-style judge overlay above the legacy hex judge effects. `MuriRenderOptions::showChartReviewSlideJudgeOverlay` controls slide/wifi-family overlays and defaults to enabled; `showChartReviewTapJudgeOverlay`, `showChartReviewBreakJudgeOverlay`, and `showChartReviewTouchJudgeOverlay` separately control tap/hold text, ordinary break text, and touch/touch-hold text overlays.
- Native chart-review tap-family judge text distance defaults to `inner`, which places the `PERFECT`/simple judge text closer to the note judge effect. `middle` is an intermediate offset, and `outer` preserves the legacy distance. The setting is shared by realtime preview, export preview, cover chart-frame rendering, and video export snapshots.
- In `RenderMode::MaimuriDxStyle`, wifi track erasure currently follows runtime lane progress rather than static area checkpoints: the shared track trims by the slowest of the three lanes, falls back to judged lane areas if the progress array is unavailable, and stays erased after runtime completion instead of replaying a full-track flash. When `MuriRenderOptions::wifiNeedC` is enabled, the last area stays visible until `C` is actually released.
- Export auto-encoder selection currently favors conservative H.264-oriented paths in automatic mode before falling back.
- Export settings now expose an application-scoped preset row in both single-export and batch-export dialogs. `Fast` is the default and preserves the previous speed-oriented baseline; `High Quality` and `High Compression` stay codec-agnostic in the UI but remap encoder-specific knobs underneath. With the D3D11 export backend, the Quality preset does not change backend selection or readback behavior: D3D11 always uses synchronous staging-map readback, so the option should not be treated as a D3D11 backend speed switch.
- Export FPS is an export-only dialog preference shared by single export and batch export through the embedded settings panel. The selectable FPS values are currently `30`, `60`, and `120`; the default seed remains `60`, and stored/custom task FPS values are snapped to the nearest selectable option with halfway values choosing the higher option.
- Full-range export currently uses a `2.0`-second lead-in. Partial export keeps a separate `1.0`-second preload. PV/BGM start at `timelineOriginSecond = segmentStart - preload`. Lead-in / preload frames clamp the renderer playhead so the playfield + HUD render the chart frozen at segment-start (`exportSecond = qMax(0.0, timelineOrigin + outputSecond)` for full-range, `exportSecond = segmentStart` for partial) instead of producing a black / transparent pre-roll; the HUD timestamp uses `hudPlayheadSecondsOverride = rawChartSecond` during the lead-in / preload so it counts up through the negative chart time (`-2s → 0s` for full-range; `segmentStart-1s → segmentStart` for partial). Export filters objects up front by `marker.second` within the simulated frame window `[timelineOriginSecond, R]`; slides and their tracks stay coupled to the head timestamp because the whole `TimelineNoteMarker` is either kept or dropped as one unit.
- Export output naming currently auto-appends `.mp4` when missing and avoids collisions by choosing `name(1).mp4`, `name(2).mp4`, and so on before the worker starts.
- Export range timestamp edits accept compact minute-based input (`MM`, `MM:SS`, or `MM:SS:mmm`) and normalize back to `MM:SS:mmm` on commit. Full-width Chinese colons are treated as ordinary colons, while other Chinese text is rejected by the range input rather than being silently parsed.
- Top-level Tools menu export actions are direct dialog launchers for batch export and cover export. When the export hub page is active, these actions use the export page's selected difficulty badge because `activeDifficultyId_` is intentionally cleared while that page is shown; the shared menu helper falls back to that selected badge even if the page-session guard is not active yet.
- The export hub page keeps `activeDifficultyId_` cleared, but its editor/workspace column minimum width must still match the normal difficulty-page header baseline: difficulty label, Lv plus offset/designer controls, validation summary, and cursor. Do not let it collapse back to the lower generic workspace floor just because the visible header only says `Export`.
- Net batch download and upload are paired top-level Tools menu items, separated from the export actions, and both remain available from the outline Toolbox entry. Each upload-folder browse appends the selected directory itself plus valid immediate child folders to a path-deduplicated queue; a valid bundle requires `maidata.txt`, `track.mp3`, and a `bg.jpg` / `bg.jpeg` / `bg.png`, accepts optional `pv.mp4` / `bg.mp4`, and sends one authenticated multipart request per queued chart. Uploads are sequential with a cancellable 5-second pause between completed non-fatal items. Failures expose complete copyable diagnostics without credentials/cookies; when a batch ends with unsuccessful charts, the result prompt reports their count and offers Cancel or Upload Failed Again, with retry limited to unsuccessful rows so successful charts are never resent. Rows left unattempted by a fatal batch stop count as unsuccessful retry candidates. HTTP 413 is an oversized-request/chart failure and takes precedence over Cloudflare markers injected into its HTML error page, so it advises video compression and does not stop later charts. 429/Cloudflare 1015 observes `Retry-After` and retries once, while repeated limiting, authentication/access failures, and genuine Cloudflare challenges stop the batch. Majdata credentials are persisted in application preferences only when the user explicitly enables the remember-credentials checkbox; retry can reuse them only in memory for the current open-dialog session.
- Batch video compression uses the same cumulative-list and folder-depth interaction as Net batch upload: each browse appends the selected directory and its readable immediate child directories only, duplicate directory paths are ignored, selected rows are only for list removal, and every scanned folder remains visible even when it has no video. Each folder resolves `bg.mp4` before `pv.mp4` case-insensitively. Rows explicitly report `No video`, `Already under 20 MiB; not compressed`, `Compression succeeded`, or `Compression failed`; only videos over 20 MiB are transcoded and counted as successes/failures. Compression keeps `<video-stem>_bak.mp4`, rejects outputs that are not both smaller than the input and at most 20 MiB, and preserves a `_compressed` output when in-place replacement is blocked.
- Cover export currently uses a standalone Cover Studio fixed workbench: a non-dockable native `QMainWindow` with fixed layer, preview, inspector/settings, and frame-picker regions. It keeps the existing user-visible cover-export entry wording. The renderer remains MiaCode's own `CoverComposerView` / `SceneFrameRenderer` path; no external editor, docking, or property-browser dependency is part of the first implementation.
- Cover Studio chart-frame layers are first-class composition layers. Multiple chart frames can be visible, but only the active chart-frame hosts a live `PreviewQuickSceneRoot`; non-active frames use cached stills and all visible frames are refreshed at export resolution before final PNG/JPG composition.
- Cover Studio chart-frame inner background is per layer. `Jacket` mode uses the cover background with the brightness slider; `Transparent` mode draws a black disk whose transparency slider runs from solid black at 0% to no background at 100%. The chart-frame layer opacity only fades the note/ring overlay, not this inner background.
- Cover Studio and export intro share the `MaimaiBannerCard` template; the `NOTES DESIGNER` label stays blue, the designer value uses the sampled muted blue-gray `#8091AE`, and the `BPM` text uses a neutral gray.
- Export intro difficulty-card chart type defaults to Auto. Auto resolves to DX when the parsed chart contains touch, touch-hold, break hold, a slide/wifi track marked break, a multi-segment slide/wifi, or protected `x` (`isEx` / `headEx`); otherwise it resolves to Standard/SD. Manual DX/SD selections still override the detector.
- Cover Studio chart-frame transport keys are centralized in `CoverStudioPanel`: Space toggles visual playback, Left/Right tap by 1/120 second, Left/Right hold uses the shared preview held-seek acceleration, and key release/focus loss/window deactivation cancels the hold.
- Cover Studio canvas hit-testing is centralized: blank clicks clear selection, overlapping layers choose the currently selected hit layer first and otherwise highest z first, and adding a chart frame inherits the last selected chart-frame settings except position. Canvas visual zoom is edit-view-only: it resizes the embedded preview viewport for inspection and must not persist to `.miacover`, normalized layer geometry, or final export size.
- Cover Studio's layer list is a custom-delegate control, not a checkbox list: rows show a thumbnail, visibility eye, lock glyph, name, and subtitle. Clicking the inline eye or lock updates that layer by key without changing the current selection; non-active chart frames restored to visible get a cached still if needed.
- Cover Studio layout presets live under `app.cover_export.presets` as user preference data, separate from the saved `.miacover` schema and recent-file list. User presets are saved without `size` so applying them keeps the current canvas size; built-in presets are constant UI entries and are not persisted.
- Background media naming is currently limited to `bg.*` or `pv.mp4` style conventions.
- Project editing currently anchors field-dirty state to explicit save points instead of relying on Qt's generic modified flag alone: chart text uses the document undo position as the save anchor, while line edits compare against the last applied document values.
- Chart metadata now treats `&clock_count=` as a defaulted extra metadata field. New or loaded documents without an explicit value surface `&clock_count=4` in the metadata page's "Other &xx Fields", and serialization/save paths preserve or restore that default. The latency settings page exposes the same field next to BPM/Offset and writes it through the metadata extra-field store.
- Autosave side effects now live under `<chart dir>/.miacode/`: project state uses `miacode_settings.json` for chart-local navigation metadata such as the last opened difficulty, default logs resolve to `.miacode/logs/` once a chart is bound, and per-chart autosave uses `.miacode/.autosave/<chart file>/`. Preview/video/audio/timeline/render preferences are application-scoped and must not be overwritten when switching chart folders.
- The main-window size preference records only the normal-window width/height ratio as `app.window_aspect_ratio` in application preferences. Startup applies that ratio to the default 1280x800 area and current screen bounds, instead of restoring absolute pixels, so cross-screen and DPI changes keep the app usable. This is separate from preview/export canvas aspect-ratio settings.
- Dragging a folder onto `MiaCode.exe` or its shortcut is treated as a startup open request for `<folder>/maidata.txt`. If that file is missing, the app clears any restored last-session chart back to the default welcome page and shows a localized warning naming the dropped folder. Dragging a file still opens that file directly.
- Autosave currently has split `latest` vs `history` behavior. `latest` writes `<chart file>.bak` after about 2 seconds of idle editing, and also refreshes on window deactivation, file switch, and close; it overwrites in place and is not deleted on manual save. `history` writes into `history/YYYY-MM-DD-HH-MM-SS.bak`, is driven only by the 2-minute autosave timer, and writes only when the content differs from the previous history snapshot. If multiple history writes land in the same second, the later one replaces the earlier file and metadata is rebuilt to match.
- Autosave history currently keeps at most 30 files per chart. When the limit is exceeded, pruning removes the oldest history file first.
- Each chart autosave container currently carries a rebuildable `autosave.json` summary. If the file is missing, the next autosave pass recreates it by rescanning the on-disk `latest` and `history` contents.
- Preview panel layout is currently card-based. In quick shell, the embedded preview pane now keeps the square preview canvas on top and renders the transport card plus stats card as pure QML under it, while the classic widgets backend keeps its own native cards for non-quick-shell mode. QuickShell window resizing, preview splitter dragging, sidebar width changes, editor-header minimum-width changes, export aspect-ratio switches, and bottom-tabs height/visibility changes all must re-clamp the preview pane from the bounded visible workspace width; inline preview and DComp tracking must wait for stable embedded frame geometry instead of binding at 0 or tiny sizes. In normal editor preview the canvas stays the largest centered square.
- On-screen preview is currently hosted by `PreviewRuntime` through `QQuickView + QWidget::createWindowContainer(...)`, and both realtime preview and export now render through the Qt Quick scene graph plus `PreviewQuickExportSession`.
- New preview or export rendering work should prefer adding another dedicated `scene/` state builder or `quick_scene/` layer file instead of reintroducing a painter/OpenGL fallback path.
- Preview fullscreen currently shares the same quick-shell transport component as the embedded quick-shell preview, keeps the rounded translucent-black `Esc` hint bubble, and only reveals a near-full-width bottom overlay control bar when the cursor moves into the bottom hot zone, with fade-in/fade-out opacity animation before auto-hiding again.
- QuickShell embedded and fullscreen inline preview surfaces are created lazily once, then kept resident and routed by visibility/binding. This trades a higher steady-state texture-cache footprint for avoiding GUI-side Loader destruction during F11 transitions; scene-graph invalidation remains responsible for render-thread resource teardown.
- Preview fullscreen currently forces that bottom overlay control bar into a deep-night palette regardless of the app-wide light/dark theme, so fullscreen transport stays readable against bright preview content.
- Preview audio settings currently expose one global row plus Majdata-View-style bucket rows in this order: `Track`, `Answer`, `Tap`, `EX`, `Break`, `Break Slide`, `Slide`, `Touch`, `Firework`, followed by a checkbox that can filter the break-slide tail `break.wav`. The global slider scales every preview sound path together, its mute button mutes or restores all rows as one snapshot, and adjusting it auditions the `answer` cue. Per-row mute buttons still work independently; restoring one row while the global mute snapshot is active also restores the global volume, but other rows stay muted.
- Preview SFX kind-to-volume mapping now uses direct bucket gains in `src/audio/PreviewAudioSettings.h` for both realtime preview and export mixing: `answer -> Answer`, `judge -> Tap`, `ex -> EX`, `judge_break / break_touch / break -> Break`, `break_slide / break_slide_start / break_slide_finish / break_slide_tail_break / judge_break_slide -> Break Slide`, `slide -> Slide`, `touch / touchhold -> Touch`, `firework -> Firework`, `clock -> Answer`, and the song track uses `Track`. Same-second same-kind SFX still collapse to one playback that keeps the strongest event gain, every note-SFX kind still runs latest-wins across time, touch-hold sustain stays a shared non-stacking runtime/export voice, and break-slide tails fire a flagged ordinary `break` event plus `judge_break_slide`; the flagged break tail is routed to the Break Slide row as `break_slide_tail_break` after filtering while still using `break.wav`. New-session defaults are `Global 30`, `Track 100`, `Answer 80`, and `30` for the remaining bucket rows.
- Preview timing settings currently have no dedicated UI yet. They are persisted separately from preview audio volume settings, default to zero offsets, and are still consumed by both realtime preview and export through the shared timing helper path.
- The chart text editor and metadata multiline text area now leave `Ctrl+Enter` / `Ctrl+NumpadEnter` to the text widget as a plain line-break insert; preview play/pause no longer hijacks that shortcut from text editing.
- Comment-derived sidebar bookmarks are one-shot navigation actions, not a persistent current-position state: clicking one centers the target source line in the chart editor, seeks the Timeline/preview cursor to that line's resolved chart second, and then clears the sidebar's transient bookmark selection. `Ctrl+click` follows the same path as an ordinary click. Inline rename uses the same compact bookmark-name font as the painted row.
- The chart text editor's half-width input preference is application-scoped, defaults to enabled, and normalizes full-width punctuation/symbol input to chart syntax equivalents instead of filtering Chinese text content. Full-width comma `，` remains a beat comma `,`, while ideographic comma `、` is a slash-each separator `/`. Pasted content should stay intact and should not run through the half-width conversion path.
- The chart text editor keeps its custom right-click menu on the text area and line-number/bookmark gutter, but disables the native scrollbar right-click menu on its vertical and horizontal scrollbars.
- Preferences dialog controls that bake theme colors into widget-local stylesheets, such as its close/background buttons and background sliders, are registered and refreshed when the app or system color scheme changes while the dialog is open.
- The chart text editor's bracket auto-completion treats selected text as replaceable input: typing `[`, `{`, or `(` over a selection deletes the selected text, inserts the empty matching pair (`[]`, `{}`, or `()`), and parks the caret inside instead of surrounding the previous selection. Typing `[` immediately before an existing `[` steps into that bracket instead of inserting a duplicate pair.
- The chart text editor's difficulty-switch view preservation preference is application-scoped, defaults to enabled, and lives under Preferences -> Editor. When enabled, switching between existing difficulties preserves the editor scrollbar value if the target chart has enough lines, clamps to the last line if not, and restores the same paused/authoritative preview second only after the new difficulty's slow timeline/preview refresh has published a valid snapshot so the slider, preview canvas, timeline playhead, and QuickShell route stay aligned instead of briefly resetting to `0:00`.
- The chart text editor now keeps the caret visibly rendered at line-start on non-empty lines; the older special-case "hide the caret at column 1" behavior is retired.
- When the chart text editor shows block-spacing gaps between lines or trailing blank space below the document, clicking that blank region currently snaps the caret onto the previous real line at the closest horizontal x-position instead of doing nothing or jumping straight to end-of-document.
- Selection-based chart transforms that go through the shared chart-editor selection-transform path (`mirror`, `rotate`, `Toggle Break/EX/Firework`, `Random Rotate`) now store explicit undo metadata: `Undo` restores the pre-transform selection, and `Redo` restores the transformed selection. This selection restoration does not extend to `Format Chart`, ordinary typing, metadata multiline text, or `QLineEdit` undo stacks.
- When the chart editor or metadata multiline text area owned focus before the whole main window deactivates, reactivating the main window currently restores focus and caret/selection to that same text widget unless another focusable child already claimed focus during reactivation.
- Clicking the embedded preview surface now transfers real focus into the preview scope instead of leaving text focus behind; after that handoff, preview keys such as `Space`, `F11`, `Esc`, and left/right seek stay on preview until the user focuses a text widget again.
- Once any text-input widget owns focus (`PlainCodeEditor`, metadata multiline text, `QLineEdit`, or find/replace inputs), unmodified `Left` / `Right` now stay with text editing and immediately clear any in-progress main-window preview held-seek state instead of letting preview keep moving underneath the editor.
- While the preview time slider has focus, pressing `Space` currently forwards to the same preview play/pause transport; clicking or dragging the slider keeps that focus on the slider.
- While the preview time slider has focus, `Left` / `Right` currently move exactly one `120 FPS` frame per discrete press. Held seeking uses a dialog-owned timer instead of OS key-repeat timing, ramps linearly from `1x` toward `3x` equivalent playback speed, and the slider wheel uses that same one-frame base step.
- While any protected child dialog or progress window is visible, main-window preview shortcuts no longer bleed through into the underlying editor/preview surface. Plain child windows block main-window `Space`, `Left` / `Right`, and `Ctrl+Shift+X` / `Ctrl+Shift+C`; `Export Video` and `BPM & Offset Detection` keep local ownership of `Space` plus `Ctrl+Shift+X` / `Ctrl+Shift+C` for their own transport controls, while still blocking main-window left/right seek bleed-through.
- On the export video page, local export-panel play/pause shortcuts and buttons must route full-range `Add intro` playback at chart `0s` through the main preview intro state machine. The export intro lead-in counts as a playing preview state for local pause/UI decisions, so pressing `Space` again pauses the intro instead of starting ordinary chart playback underneath the overlay.
- Animated intro banner title/artist/designer text should keep a readable fixed size and, when too long, loop horizontally inside a clipped window with side padding so the text enters and exits through the field margins. Still cover/card export remains static and keeps the existing shrink/ellipsis policy.
- In quick shell, when the visible root window receives a close request while blocking modal Qt dialogs are open, close handling now prefers the main window: current blocking modal dialogs are closed first, then the normal shell close path runs once. If the shell-close confirmation is cancelled, the app stays open and those child dialogs are not automatically restored.
- In quick shell, embedded preview transport/stats are now pure QML. `Left` / `Right` seeking goes through controller-level step/held-seek methods instead of forwarding native `QSlider` key events, and both embedded preview focus scopes plus fullscreen use that same backend seek timer/step path.
- Preview render settings keep the existing `autoPreviewOutlineVariantForChart` default-selection rule (`Line` when background media exists, `JudgeAreaLabeled` otherwise), and the gameplay settings now include a persisted `force_labeled_judge_line_when_paused` toggle that defaults to enabled. When that toggle is on, paused positioning paths such as timeline scrubbing, preview-slider dragging, and left/right frame stepping keep the preview in a non-playing state, hide PV/BG, temporarily force the displayed judge-line variant to `JudgeAreaLabeled`, and restore the user's selected variant/custom outline plus stage-media visibility as soon as playback resumes. If a custom outline is selected for that paused helper view, the runtime composites the custom outline with only the judge-area region/label overlay derived from `outline_area.png` and `region_labels_overlay_transparent_v3.png`; the built-in default `outline_line.png` ring is subtracted so it does not stack on top of the custom outline.
  - While the paused preview judge-area helper is temporarily shown by holding the pause-display key (default `Alt`), hovering a Touch area on the preview draws a shallow white mask over that pad, and left-clicking inserts that Touch pad token (`C`, `A1`..`E8`) at the chart editor's current caret/selection and returns focus to the editor. The preview Video settings include a persisted Touch-area click-input checkbox that defaults to enabled and gates this hover/click shortcut only. Hover and click share the same logical Touch pad geometry as the parser/preview; this is an editing shortcut only and does not affect playback or export.
- Background/PV scale mode includes `square_fit`, which fits the full media inside the largest centered 1:1 square of the current canvas, keeps the outside area black, and does not follow the layout-size slider. It also includes `inner_circle_fit_outer_fill`, which fill-crops the media for the outer canvas while drawing a second fit-contained copy clipped to the layout-size inner circle so the center playfield keeps a 1:1 fit view.
- While the Timeline view itself has focus, pressing `Space` currently forwards to the same preview play/pause transport; the Timeline header controls keep their own default widget behavior.
- While the Timeline view itself has focus, `Left` / `Right` keep the existing horizontal-viewport movement semantics instead of syncing playhead/cursor state. Discrete presses keep the widget's existing single-step behavior, and held navigation caps its equivalent playback speed at `2 * current zoomScale()` (for example `25% -> 0.5x`, `50% -> 1.0x`, `100% -> 2.0x`).
- Timeline drag/scrub currently edits runtime `R`, not editor-anchor `C` only while `Progress Follow` is enabled: dragging or wheel panning first pauses playback, rebinds `R` to the viewport center when needed, keeps the yellow progress line visually centered during drag, and seeks preview to that centered time; with `Progress Follow` disabled, drag and wheel panning move only the timeline viewport and do not pause, seek, or affect playback. Header clicks and `Ctrl+click` on the timeline still perform the spec's `R -> C` action by click second, and editor-side cursor updates only move `C`.
- Timeline playback currently keeps runtime `R` visually centered in the Timeline viewport while preview playback is running; paused positioning still uses the existing explicit-center vs keep-margin rules from the caller, and the Timeline-side playhead/UI refresh cadence is fixed at `30 Hz` independent from the preview canvas frame-rate mode.
- Timeline waveform rendering currently applies a one-preview-frame phase compensation based on the preview canvas frame interval, so waveform peaks appear one preview frame earlier than their raw cache timestamp. This is an explicit rendering-layer default based on logs from 60 Hz and 120 Hz devices showing the authoritative audio clock leading the timeline-rendered playhead by about one frame; the root cause remains unknown, and current evidence does not prove the compensation should scale with playback rate.
- Timeline zoom currently offers fixed presets from the timeline state bridge; when no stored application preference exists it starts at `50%`, the QuickShell header zoom control opens an upward preset menu from its body and uses the right-side upper/lower hit zones to step zoom in/out, and the selected preset is cached in portable preferences as an application-scoped setting rather than a per-project render state. In QuickShell, the zoom control is the only left-side header control. The right-side transparent header button opens an upward brightness menu with waveform and grid-line sliders; both values are cached in portable preferences as application-scoped settings. Header labels and line-start markers avoid the restored right-side button, while grid-line brightness applies to meter-driven bar lines (`gridMajor`), within-measure beat/subdivision lines (`gridSubdivision`), and comma/note-position ticks (`gridMinor`). Code Follow stays user-visible in the bottom tab strip; View Lock is hidden and fixed to `true`; Progress Follow is hidden and fixed to the original default `true`.
  - Timeline wheel zoom is exposed through the editable shortcut registry as `timeline.zoom_in` / `timeline.zoom_out`, defaulting to `Ctrl+WheelUp` / `Ctrl+WheelDown`. Both the Quick timeline item and the legacy QWidget timeline read the same configured wheel gestures; the older hardcoded `Alt+wheel` path is no longer a zoom shortcut unless the user explicitly rebinds it.
- Bottom-tabs Timeline content can now be vertically resized by dragging the invisible hot zone at the top edge of the bottom tab host. Timeline content primitives and fonts scale together from `100%` down to `50%`, while stroke widths stay fixed. Timeline header controls/line labels, the bottom-tab strip (`Timeline` / `Syntax Check` / `Muri Check` plus the Code Follow checkbox), and Validation/Muri list fonts follow the derived header scale from `100%` down to `75%`. Timeline height is computed from the scaled header plus scaled lanes, without an extra trailing content padding. The existing `25%` timeline zoom special case remains visually pinned to `50%` material size, including slide-track sprites.
- Timeline header line number font now uses the same base monospace font and point size as the chart text line-number area, while still keeping the existing per-digit-count / width-budget shrink logic for 2+ digit labels.
- Timeline header line numbers currently anchor to each source line's own `startSecond`, not to measure-line positions. When multiple source lines collapse onto the same visible anchor, the later line number wins; later anchors that land within the minimum header spacing stay hidden until a sufficiently separated line start appears. Each displayed anchor also draws a small inverted triangle marker in the same color, with its tip and side angle aligned to the playback-entry triangle directly under the label. Header labels now size per digit count instead of per visible batch: 1-digit labels use a slightly reduced base font, 2-digit labels shrink a bit further, and 3+ digits keep shrinking by their own width budget while staying bottom-aligned to the 1-digit baseline. Quick/DComp header labels and line-start markers prefetch one viewport around the active scroll bucket and rebuild only when the bucket changes, so paging within a bucket remains transform-only.
- Timeline beat-grid currently treats every comma as a beat line, and draws measure lines on a separate meter-driven timeline (currently default 4/4, but parameterized as meter numerator/denominator for later meter support). `{beats}` changes only affect comma spacing, while real `(BPM)` switches restart the measure-line timeline at the BPM-change position.
- Timeline beat-grid drawing currently caps dense comma grids at `32` subdivisions for rendering only: when a source `{beats}` value is denser than `32`, the Timeline view draws the largest divisor `<= 32` instead of every raw comma line, without changing cursor anchors or parser timing.
- Timeline measure lines currently stay in the same border-adjacent gray-blue family in both themes, but use a more pronounced shade than the base border so they read more clearly. Regular beat lines reuse the same subdued tone as the horizontal lane separators. Waveform fill is intentionally higher-contrast than before: darker in light theme, lighter in dark theme.
- Timeline note layering currently mirrors the preview object order for overlapping sprites: firework tails underlay the note stack, slide/wifi tracks draw first, tap/hold/slide/wifi heads share the preview-style descending-`second` stack, touch draws above those heads, and touch-hold draws above touch.
- Timeline hold strips currently scale their cap thickness to match the preview hold-to-tap ratio (current target `60:61`, derived from preview hold width vs tap width).
- Slide/wifi synchronous color state currently splits head-vs-track semantics: `headEach` follows the synchronous note-head group, while `slideEach` turns on for multiple slide-like notes inside the same slash each-group regardless of `#` / `##` timing differences. The later slow-refresh trace grouping still protects against unrelated older slides inheriting yellow just because a later each-group reaches the same shoot moment.
- Slide/wifi `m` syntax currently marks only the track as mine (`trackMine`); the slide head star keeps the original star material instead of using the mine/gray star.
- `hasHeadStar` currently means "the pre-head object exists"; it still controls head SFX / head judge / head review overlay. `?` / `!` do not re-enable those paths, and `headlessImmediate` only changes the waiting-star visual ramp.
- `$` / `$$` / `@` are currently material-only syntax: they change head rendering and timeline iconography, but they do not alter note timing, break/ex ownership, or slide track semantics.
- Preview follow currently updates the editor cursor binding during active playback without forcing the editor scroll position, so users can inspect earlier or later code while the followed caret/decorations continue updating off-screen. When follow-preview is enabled but preview is paused, the editor-side blue follow decoration tracks the Timeline playhead (the blue line) using the same latest-past-comma anchor lookup as playback follow, highlights the whole pre-comma segment instead of just the comma, and paused seeks reveal that segment in the editor viewport without moving the editor caret. The follow-preview toggle is an application-scoped preference cached in portable preferences, not a per-project render setting.
- Preview playback currently freezes a play-start snapshot for preview video/SFX/object stats until playback stops; live text edits still redraw the timeline and refresh validation/Muri inputs, but they do not rewrite the content that is already playing. Starting or resuming playback should take that frozen snapshot from the latest in-memory chart state, even if the asynchronous slow refresh has not landed yet. Playback start/resume now seeds that snapshot directly from the chosen runtime clock without a follow-up calibration tick.
- If the user requests play/resume before the newest preview snapshot is ready, playback now stays paused and auto-starts when that revision's preview snapshot arrives; no extra waiting UI is shown.
- Validation and Muri feedback are lower-priority than preview playback: workers may continue to refresh their latest results while preview playback is running, but panel/decorations are allowed to apply on the next paused/idle edge instead of competing with the active preview path for immediacy.
- Timeline analysis currently runs as a single-source pipeline: one slow-refresh parse publishes the preview snapshot, then one latest-only analysis request builds both validation and Muri results from that same parse output and note-marker snapshot. Analysis-only setting changes should prefer reusing that cached snapshot instead of forcing another full parse when possible.
- Validation UI currently emphasizes surfaced issues in the bottom tabs and summary chips in the editor header.
- Validation and Muri bottom-tab rows currently render through one shared rich-text delegate rather than per-row child widgets. Keep row-height recompute batched per list refresh/resize instead of doing one synchronous full-list relayout per inserted issue row.
- Chart validation severity for chained slide duration placement is a parser contract: final-segment-only duration is valid, every-segment duration is a Warning because it is only partially supported, and partial/misplaced duration after a non-final segment is an Error. Strict validation should not silently discard slide suffix text or empty `*` branches; current audit evidence and examples live in `docs/specs/chart/CHART_DIAGNOSTICS_AND_NORMALIZATION_SPEC.md`.
- Mine notes use lowercase-only `m`; uppercase `M` is invalid in the main parser and mirror parsers must not canonicalize it into a mine.
- Whole-chart formatting currently preserves ordinary mid-measure `||` comments by splitting them onto their own lines instead of treating them as time-signature controls, minimizes `{beats}` at one-beat granularity instead of promoting the whole rendered line to the densest local subdivision, ignores hold/slide duration syntax when choosing that rendered `{beats}` value, and can optionally rewrite no-`#` hold/slide `beat:num` durations onto the nearest `384`-grid form while leaving original `#`-based timing signatures untouched. The chart-format dialog uses styled dropdown rows for fine-tuning: `reduceTo384Grid` is available as "on/off" and is not selected by default in the app, while `splitEveryFourMeasures` defaults to inserting a blank visual section after every 4 emitted measure lines and can be changed to no sectioning. The old "selection start as measure boundary" UI option is removed from the dialog, and the app entry fixes that behavior on so hidden legacy preferences cannot leave selection formatting in the old off mode. Chart-format dialog option changes are saved to application preferences immediately when changed, even if the dialog is later canceled; cancellation only skips applying the chart rewrite. In exact non-`384` mode, no-`#` duration signatures now prefer the active rendered `{beats}` value when that grid can represent the duration exactly; in `384`-snap mode, rendered duration signatures still do not simplify past a `16th-note` denominator floor. Zero-length note-holds may collapse to bare `h`, while slide durations stay at least `1/384` so normalization does not emit illegal zero-length slides. Adjacent beats on the same output line may omit repeated `{beats}` prefixes when the value does not change.
- Chart normalization segment policy is intentionally segment-scoped: `reduceTo384Grid=true` may snap non-384 timing onto the 384 grid but must emit a subdivision that exactly represents each snapped segment length; `reduceTo384Grid=false` preserves non-384 explicit rest/note segments unless their start and end both sit on the current meter's half-beat grid and exact minimal rendering can safely simplify them. Selection formatting appends a trailing `{N}` only when following text would consume the current subdivision before `E`, another `{N}`, or an ordinary `||` boundary.
- Muri diagnostics UI currently merges runtime diagnostics and static references into one time-sorted list, but runtime entries win when the same Muri kind hits the same anchored `LxCy`; static references act as fallback-only supplements. Static references currently surface `SlideHeadTap`, `TapOnSlide`, and `Overlap`. Runtime and static `SlideHeadTap` / `TapOnSlide` anchors now follow the affected object token rather than the earlier contributing slide/wifi token, while runtime `SlideTooFast` rows that resolve to `"... was early-judged by ..."` anchor to the latest external cause token; overlap/multitouch-style rows still prefer the earliest contributing object. Muri-row clicks jump the editor to the stored `line / col` exactly while preview/timeline seeking can still use the stored anchor second, same-moment overlaps collapse to at most one visible row, and `SlideHeadTap` / `TapOnSlide` detail strings name the affected target as `tap N`, `hold N`, `star N`, or the full normalized slide/wifi chain token instead of truncating chained slide descriptions to the first segment. For both `SlideHeadTap` and `TapOnSlide`, affected targets that carry protection (currently EX / head-EX targets) downgrade to `Warning`; warning wording stays tentative (`may ...`) while `Muri` wording stays definitive. `SlideHeadTap` also downgrades to `Warning` when the slide has no startup tap and `0 < gap <= 50 ms`, or when `gap >= 150 ms`.
- Runtime `MultiTouch` currently keeps the existing `kReleaseDelaySeconds` tail lifetime for slide/wifi hand actions, but in the MultiTouch-only slide pre-merge path a slide pair that was already merged on the previous tick continues to stay merged through a release-tail tick instead of spawning a temporary extra cluster solely because one slide lost its sampled tangent at the end.
- Hidden `Muri` tabs currently defer full list rebuilds until the tab becomes visible again. The delayed list materialization is intentional; editor summary chips plus preview/timeline overlay publication should still advance immediately from the latest aligned analysis result.
- Runtime `MultiTouch` analysis now has an explicit render/analysis option gate: when `MuriRenderOptions::excludeTouchFromMultiTouch` is enabled (default), touch-derived actions (`touch`, `touch-hold`, and grouped touch clusters) are filtered out before multi-touch hand-count clustering. The option is persisted through preview/project render settings and export snapshots so preview analysis and export-side reanalysis stay aligned.
- The outline Toolbox entry currently surfaces `Muri Check`, `Format Chart`, `Batch Video Export`, and an external `Official Chart Mirror` link; the Help menu currently surfaces `Official Chart Mirror`, `simaiwiki`, and then `About`.
- Runtime `SlideTooFast` currently only reports when the slide or wifi is actually completed by another note's pad-down on its final judging step. If a long slide runs out of meaningful external input and only self-completion remains, Muri analysis treats it as a normal pass, suppresses the `SlideTooFast` row, and emits no slide `Good` overlay.

These are adjustable, but if changed they should be documented here and in the relevant index/linkage files.

## 4. Areas That Are Intentionally Flexible

- UI polish details such as spacing, card proportions, and control arrangement
- tuning values for visual effects, so long as linked render/export assumptions remain coherent
- packaging behavior for dev-only helper executables
- exact wording and severity presentation of validation and diagnostics UI
- export heuristics such as bitrate, encoder preference order, and progress reporting, as long as the worker contract remains intact

## 5. Areas That Need Guardrails

- Path resolution rules are still duplicated in a few places, especially for media and track files.
- A large amount of visual tuning still lives in implementation-local constants across `src/core/scene/*.cpp` and `src/tools/video_export/VideoExportController.cpp`.
- Latency detection carries algorithm-specific constants that are meaningful but still mostly local to the tool.
- Packaging and debug docs still need occasional sync when Qt Quick runtime requirements or export diagnostics change.

Treat these areas as change-sensitive even when the underlying behavior is adjustable.

## 6. Explicitly Open Or Risky Areas

- Whether duplicated path-resolution logic should be centralized further
- Whether more preview/export configuration should move from implementation-local constants into shared config headers
- Whether some current chart-directory filename conventions should become configurable
- Whether the repository should gain scripts to auto-refresh code maps and hardcode registries instead of manual upkeep

## 7. Decision Logging Rule

When a previously flexible area becomes a hard contract, add it to section 2.

When a hard contract is intentionally relaxed, remove or rewrite the old rule instead of layering contradictory text on top of it.

When a design choice is still under discussion but the current code depends on it, write it here as "current default" or "open/risky", not as a permanent rule.
